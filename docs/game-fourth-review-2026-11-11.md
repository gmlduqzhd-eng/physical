## 검증

- 최종 `npm run verify:release`: 222개 검사(노드191·실행26·새로고침5), 전체 린트·서버 타입 검사·학생 및 교사 빌드 통과. 이번 회귀시험은 18개이며 실제 컴포넌트를 모의 시계·SDK로 실행하는 9개 시나리오를 포함한다.
- 실제 컴포넌트 회귀 시나리오: 스트레칭 정지/재개와 일부 수행, 033 과제 선택 초기화, 리듬 요청 대기/실제 중단 구분, 그림자 입력 변경 후 보존, 구조 비행 정지·각도 고정, 컬링 특정 시도 교체, 감정 A 재시도 시 B 유지, 안전 재학습 중복 보상 방지, 수업 상태 읽기·오프라인·복구·종료·정리.
- 운영 Supabase에서 롤백 트랜잭션으로 75개 검사 통과. 새 조종권·일시정지·다른 교사/만료 사용자 읽기 거절 검사를 포함한다. 합성 인증·방 자료는 트랜잭션 밖에 남지 않는다. 기존 서버가 필요한 검사를 이미 수행하므로 새 마이그레이션·권한 변경은 필요 없다.
- 브라우저 합성 화면: 스트레칭 1개 수행/2개 휴식의 partial 결과, 정지 중 inert 입력 차단과 재개, 조종권 만료/다시 맡기, 지도 의견 수·불일치 안내, 로봇 복사0개/한 부위 변경1개 진행 조건, 두 마디 연습, 033 다음 과제의 미선택·시작 불가, 표현 속도1.6배·짧은 카드, 안전 세 상황→다른 상황→원래3/3 읽기 학습 결과를 확인했다. 실제 학생 DB 기록 없이 실행했다.
- 위 합성 게임15종의 초기 화면을 요청 폭390·768·1440으로 확인한 45개 조합에서 문서 가로 넘침과 시스템 오류 화면이 없었다. 리듬·033·표현·안전의 진행 화면도 모바일 폭에서 확인했다. 이는 실물 기기의 터치·카메라·기울기 정확도 시험이 아니다.
- 실제 빌드 /play/stretch에 접근할 수 없는 합성 수업 ID를 넣어 방 확인 전 활동 입력이 차단됨을 확인했다. 실제 교사·학생 다중 기기 수업 전체를 새로 완료한 시험으로 표현하지 않는다.

## 개인정보·운영 경계

새 개인정보 필드·브라우저 영구 기록·외부 AI 전송·비밀키·환경 변수는 없다. 방 상태는 기존 인증과 RLS 안에서 status만 읽으며 약1.5초 주기와 Realtime 알림을 함께 사용한다. 네트워크 변경 감지는 지연될 수 있고 읽기 제한시간은5초다. 이 화면 차단이 서버 권한 검사를 대신하지 않는다.

카메라·기울기는 기존 기기 내 처리와 명시적 시작 원칙을 유지한다. 실물 S25 Chrome·태블릿의 인식률, 배경 전환·복귀, 네트워크 혼잡과 실제 수업 효과는 현장 확인 대상이다. 보스 최종 성찰은 코스별 규칙 시험으로 검증했으며 실제 다중 기기 최종 완료 UI 시험은 포함하지 않는다. 기존 임베디드 수업 대기 화면 전체를 새로 검증했다고 주장하지 않는다.

## 실행·배포

기존 환경 그대로 `npm run dev` 및 `npm run dev:studio`/`npm run dev:studio:api`를 사용한다. 릴리스 검사를 통과한 소스를 Git main에 반영하고 학생 사이트를 배포한다. 별도 교사 준비실은 허용 목록81파일로 준비한 뒤 자체 릴리스 검사를 통과한 묶음을 배포·승격한다.

- 학생·교사 수업 앱: https://physical-pi.vercel.app
- 별도 AI 교사 준비실: https://physical-teacher-studio.vercel.app

배포 ID와 최종 접속 결과는 작업 산출물 `게임-4차-배포검증.json`에 별도로 기록한다.
