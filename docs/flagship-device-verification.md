# 대표 원정 6종 모바일·카메라·기울기 점검 (2026-11-09)

## 확인 범위

사용자가 갤럭시 S25를 사용한다고 알려 주었다. 현재 작업 컴퓨터에는 제어 가능한 S25/태블릿 또는 Android 디버깅 연결이 없어 **실물 S25·태블릿 시험 완료로 표시하지 않는다**. 아래 결과는 실제 브라우저 화면, 합성 미디어/센서 이벤트, 기기 안의 실제 모델, 자동 회귀 검사에 따른 결과다. Chrome Android·삼성 인터넷·Safari의 엔진 자체와 센서 정확도를 실기기에서 모두 검증한 것은 아니다.

여섯 게임의 실제 실행 화면을 각각 360×780, 393×852, 852×393, 768×1024, 1024×768 CSS 뷰포트에서 확인했다(30개 조합). 실제 document client/scroll 폭을 기록했으며 가로 넘침 0건, 활성 게임 버튼 높이 44px 미만 0건이었다. 이 크기는 대표 시험 폭이며 S25의 실제 해상도·화면 배율을 단정하지 않는다.

## 수정한 오류

1. **센서 보정**: 잘라낸 [-1,1] 입력에서 기준 각도를 역산해 큰 기울기를 제대로 보정하지 못하던 코드를 수정했다. 원시 각도를 보관해 현재 자세를 0으로 보정한다.
2. **가로·세로 회전**: 화면 방향에 맞는 beta/gamma 축과 부호를 사용하고, 회전 후 첫 유효 신호를 새 중립 자세로 잡는다. wrap-around와 유효하지 않은 값을 처리한다.
3. **저장 중 센서 끊김**: RPC 저장 중 표시와 실제 수업 정지를 구분했다. 각 입력을 저장할 때 센서 이벤트 구독을 해제하던 문제를 수정했다. 역할 상실·일시정지·화면 이탈은 센서를 끄고 보조 조작도 0으로 초기화한다.
4. **권한과 실제 신호 구분**: 우주선은 필요한 방향 센서 권한만 요청한다. 권한 허용 뒤 실제 이벤트가 오기 전에는 측정 성공으로 표시하지 않으며, 신호가 1.5초 이상 없으면 입력은 0이다. 권한 거절/미지원/신호 없음의 안내를 구분했다.
5. **카메라 오류 유지·자원 해제**: 오류 상태를 stop()의 ‘꺼짐’으로 덮지 않는다. 권한 거절·카메라 없음·다른 앱 사용·재생/추론 실패에 대응하는 안내와 터치 대안을 제공한다. 준비 응답은 20초로 제한하고 늦게 도착한 스트림·모델도 해제한다.
6. **정지한 영상의 손목 값**: 같은 영상 프레임을 반복 추론하지 않는다. 재생 중단/트랙 mute 또는 새 영상이 400ms 이상 없으면 추정값을 비워 판정을 멈추고, 장시간 갱신되지 않으면 카메라를 종료한다. 트랙 종료·화면 이탈·컴포넌트 해제 시 트랙·모델·예약 작업을 해제한다.
7. **그림자 터치**: 한 번 눌러도 점이 이동하며, buttons=0인 터치 이벤트도 활성 포인터로 처리한다. 태블릿의 SVG 여백을 고려한 실제 좌표 변환을 사용한다. 참여 방식을 바꾸면 기록과 완료 확인을 초기화하여 카메라/터치 기록이 섞이지 않게 했다.
8. **구조대 참여 방식·충전**: 터치가 포함된 수행을 카메라만 사용한 수행으로 표시하지 않는다. 참여 방식 변경·화면 이탈 시 충전을 중단한다.
9. **QR 시작·중지 경합**: 카메라 허용 대기 중 취소 후 늦게 시작한 스캐너가 새 스캐너를 끄지 못하게 소유권을 구분했다. 라이브러리가 start()를 video.play() 완료보다 먼저 반환하는 구간에서 DOM 제거로 생기던 AbortError를 재현해, 자기 카메라 재생 준비 후 정리하도록 수정했다. 종료 대기 동안 재시작을 막고 직접 코드 입력 대안을 유지한다. QR은 올바른 원정 형식만 읽으며 URL로 이동하지 않는다.
10. **모바일 소리 실패**: 리듬 소리를 켜지 못하더라도 불빛을 보고 박자 기록을 계속할 수 있고, 처리하지 않은 Promise 오류로 화면이 멈추지 않도록 했다.

## 시험 증거

- 카메라/방향 처리 자동 회귀 12개 통과: 각도·회전·보정, 방향 권한만 요청, 권한/모델 대기 중 취소, 시간 제한, 권한 재시도, 추론 실패, 정지 프레임, 트랙 mute/종료, 동일 프레임 중복 방지, 재생 실패·중단.
- 브라우저 합성 시험: 권한 거절/카메라 없음/다른 앱 사용 안내, 늦은 권한 취소 시 트랙 종료, 추론 실패 시 오류 유지, 수업 일시정지 카메라 종료, 센서 권한 거절, 실제 이벤트 도착 전 대기, 원시 각도 보정, 저장 표시 중 신호 유지, 화면 회전·신호 끊김·중립, 단일 터치 좌표 반영을 확인했다. 합성 신호를 실제 AI/운동 수행 결과로 간주하지 않는다.
- QR 합성 시험: 자기 브라우저의 캔버스 영상에 시험 QR을 그려 실제 html5-qrcode로 해독했다. 허용 대기 중 취소 2회와 QR 해독 후 자동 중지에 새 콘솔 오류가 없었다. 촬영한 실제 지점·학생·교실 영상은 사용하지 않았다.
- 실제 MediaPipe 모델을 별도 브라우저에서 합성 캔버스 스트림에 연결했다. 손목이 없는 화면에서 ‘찾지 못함’으로 판정을 막고, 중지 후 video.srcObject 해제·트랙 ended를 확인했다. 다른 시험의 SDK stub과 구분했다. 실제 인체 추정 정확도 시험이 아니다.
- 기존 release 검사와 학생/스튜디오 빌드가 통과했다. QR 보완 후 관련 타입·린트와 최종 학생 빌드를 다시 수행한다. 기존 큰 번들 경고는 남아 있으며 실행 실패로 처리하지 않는다.

출력 파일은 작업 공간 outputs의 `대표원정-기기오류-합성시험.json`, `대표원정-실제모델-수명주기.json`, `대표원정-모바일태블릿-30폭검증.json`을 참고한다.

## 갤럭시 S25·태블릿에서 직접 확인

[기기 확인 화면](https://physical-pi.vercel.app/device-check)을 Chrome 또는 삼성 인터넷의 일반 탭으로 연다. 앱 안에 내장된 브라우저에서 권한이 제한되면 기본 브라우저에서 다시 연다.

1. 기기를 거치하고 **기기 안에서 카메라 인식 켜기** → 카메라 권한 허용. 오른팔과 손목을 천천히 움직여 **실제 영상에서 추정값 수신 중**을 확인한다. 팔을 가리면 찾지 못함/판정 중지로 바뀌어야 한다.
2. **기울기 시험 켜기** 후 실제 신호 수신 문구와 입력 변화를 확인한다. **현재 자세를 가운데로 보정**하면 0에 가까워져야 한다. 세로·가로 회전 후 기기를 잠시 멈추고 새 기준으로 움직여 본다.
3. **모두 끄기**, 다른 탭으로 이동, 화면 잠금 후 복귀를 각각 시험한다. 카메라/센서가 자동으로 다시 켜지지 않아야 한다.
4. 원정 모음에서 6종을 직접 실행한다. 공동 우주선의 실제 수업 모드는 같은 모둠으로 들어간 서로 다른 인증 기기 2대가 필요하다. 지도 QR은 수업방을 연 교사의 지점 안내판으로 확인한다.

기기·브라우저 버전, 표시된 상태와 어느 동작에서 멈추는지만 알려 주면 된다. 학생 영상·얼굴·실명·API 키는 보내지 않는다. 이 화면은 기기 신호 점검이며 몸 능력 측정이나 교육 효과 검사가 아니다.

## 개인정보와 서비스 변경

새 외부 AI·DB 테이블·계정·키·유료 서비스를 추가하지 않았다. 영상·얼굴·손목 경로를 업로드/저장하지 않으며, 기기 식별자·브라우저 fingerprint도 수집하지 않는다. 기기 확인의 숫자와 상태는 화면 메모리에만 있다. 기존 수업방 권한과 7일 보관·즉시 삭제는 유지한다.

참고한 브라우저 기준: [방향 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/Window/deviceorientation_event), [방향 권한 요청](https://developer.mozilla.org/en-US/docs/Web/API/DeviceOrientationEvent/requestPermission_static), [카메라 트랙 ended](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/ended_event).


## S25 화면 피드백 이후 보완

사용자가 제공한 S25 화면에는 서버 응답 1495ms와 기울기 입력 0.77/신호 수신이 표시되었다. 이는 해당 화면에서 서버와 기울기 수신이 동작했다는 증거이며 보정·회전·수업 전체 시험을 모두 통과했다는 뜻은 아니다. 카메라는 ‘팔·손목을 찾지 못함’으로 표시되었고, 실제로 팔을 보여 준 상태였는지는 확인 중이다.

- 인식 실패를 몸 미포착·오른쪽 어깨 미포착·오른손목 미포착·어깨/손목 겹침으로 나누어 안내한다. 신뢰도 경계 .65는 낮추지 않으며, 화면 밖 좌표나 비정상 수치를 성공으로 처리하지 않는다.
- ‘내 기기에서만 카메라 미리 보기’를 선택한 경우에만 영상을 표시한다. 기본값은 꺼짐이고, 중지/오류/이동 시 감춘다. 영상·얼굴을 사진·영상 파일로 저장하거나 외부로 전송하지 않는다. 기기 확인 화면의 이전 ‘화면에 표시하지 않는다’ 문구는 이 선택형 표시 방식에 맞게 정정했다.
- 전면/후면 카메라 전환을 추가한다. 전환할 때 이전 스트림을 종료하고 새 스트림을 요청한다. 실제 방향은 getSettings의 facingMode만 확인하고 deviceId/groupId 등 식별 정보는 읽거나 보관하지 않는다. 지원되지 않는 경우 실제 방향을 확인했다고 표시하지 않는다.
- 인식 안내의 중복 출력을 없애고, 모바일 카메라 버튼은 한 줄씩 넓게 배치했다.
- 실제 로컬 모델로 Google의 공개 pose.jpg 예시를 캔버스 스트림에 넣어 인식 성공과 빈 프레임 미인식, 전환 시 이전 트랙 종료를 확인했다. 사용자의 사진이나 학생 영상은 모델에 넣지 않았다. 공개 테스트 사진은 ignored QA 경로에만 두고 소스/운영 배포에 포함하지 않는다. 이 시험은 S25 실기기 정확도 검증을 대신하지 않는다.
- 자동 기기 회귀는 14개로 확장했다(인식 실패 원인 구분·후면 입력/진단 초기화 추가).

참고: [공식 Pose Landmarker](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker?tab=Web), [트랙의 실제 설정](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/getSettings).

## 2026-11-09 · S25 Chrome 간헐 인식 개선

S25의 사용 브라우저는 사용자가 Chrome으로 확인했다. 실물 S25의 영상을 원격으로 받아 원인을 확정한 것은 아니다. 아래는 현재 코드에서 확인한 처리 부하와 재생 복구의 보완이며 실제 기기 개선 정도는 재시험해야 한다.

- 자동 모드는 로컬 GPU 추론을 우선하고 초기화 실패 시 같은 로컬 모델의 CPU 처리로 전환한다. 실행 중 GPU 추론이 실패하면 기존 판정값을 즉시 지우고 CPU로 한 번만 복구한다. 카메라를 다시 요청하거나 실패를 반복 재시도하지 않는다. 늦은 복구 응답·시간 초과·화면 이동 시 모델과 트랙을 정리한다.
- 자동 모드의 카메라 요청은 640×480, 호환 모드는 480×360을 희망값으로 사용한다. 촬영은 이상적 24/최대 30fps를 요청하고, 동작 추론 간격은 소요 시간의 두 배를 기준으로 84~300ms에서 조절한다. 호환 모드와 실행 중 CPU 복구는 최소 167ms로 부하를 제한한다. 브라우저가 실제 요청 해상도·fps를 제공한다고 보장하지 않는다.
- 이미 허용된 live 영상이 pause/unmute로 돌아오면 해당 영상의 재생만 한 번 복구한다. 권한 재요청, 새 카메라 열기, 화면을 떠난 뒤 자동 재시작은 하지 않는다. 새 프레임이 오기 전에는 판정을 재개하지 않는다. 장시간 정지와 재생 거절은 기존 값을 지우고 사용자가 다시 시작하도록 안내한다.
- ‘카메라 처리 모드’에서 **호환 모드 · 끊길 때 선택**을 고를 수 있다. 선택은 화면 메모리에만 있고 카메라를 새로 시작한다. 기기 모델명·브라우저 지문을 읽어 분기하지 않는다.
- 랜드마크 가시성과 모델 검출·추적 신뢰도 경계 .65를 낮추지 않았다. 가림·빈 프레임에서는 이전 좌표를 유지하거나 성공으로 보정하지 않는다. 모델 파일·SDK 버전도 변경하지 않았다. 영상·좌표·처리 속도·모드 선택을 서버나 외부 AI로 전송하지 않는다. 기존 모둠 준비판에는 기존 coarse 상태 enum만 전달한다.
- 기기 회귀 23개는 권한·수명주기·새 프레임·느린 추론의 부하 조절·GPU 초기화/실행 실패의 CPU 대체·늦은 복구 정리·재생 복구·실패 차단을 포함한다. 기존 원정 도메인 6개와 런타임 22개도 통과했다.
- 실제 Chrome에서 공개 `pose.jpg`를 합성 캔버스 스트림으로 넣고 실제 로컬 모델의 자동/호환 모드 인식, pause 후 동일 스트림 재생 복구, 빈 화면에서 판정 중지, 카메라 전환 시 이전 트랙 종료를 확인했다. 공개 예시 시험은 S25 카메라의 실제 촬영 정확도·발열·조명·연속 수업 성능을 증명하지 않는다. 시험 페이지는 ignored QA 폴더에만 두며 운영에 포함하지 않는다.

배포 후 S25 Chrome에서 [기기 확인](https://physical-pi.vercel.app/device-check)을 새로고침하고 자동 모드로 시작한다. 계속 끊기면 호환 모드를 선택한다. 화면 잠금·탭 이동 후에는 카메라 켜기를 다시 눌러야 한다. 학생 사진·영상은 보내지 않고, 어느 모드에서 어떤 상태가 반복되는지만 알려 주면 된다.

기술 근거: [공식 Web Pose Landmarker의 GPU 및 VIDEO 처리](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker?tab=Web), [영상 입력 복구 unmute 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/unmute_event). 실제 사진 판정은 각 인식 시점의 새 프레임에만 적용한다.

## 2026-11-09 · 모션 캠과 모든 QR 카메라 안정화

적용 범위는 기존 **모션 감지 캠 챌린지**, 학생 **수업 입장 QR**, **탐사 지점 QR**, 학생 활동 화면 두 경로의 **미션·보물 QR**이다. 앞서 개선한 손목 추정 게임·보스 관문은 그대로 유지한다. 모든 게임이 같은 인식 알고리즘을 사용한다는 뜻은 아니다. 모션 캠은 저해상도 화면 픽셀의 변화량, QR은 로컬 QR 해독을 사용하며 생성형 AI나 자세 평가로 표시하지 않는다.

- 새 공통 프레임 감시기는 새 영상·live 트랙·mute/ended·pause/waiting·6초 이상 정지를 확인한다. 일시 정지에서는 기존 스트림의 재생만 한 번 복구한다. 화면 이동·잠금·컴포넌트 종료 때 카메라를 끄고 자동으로 다시 켜지 않는다.
- 모션 캠은 실제 새 프레임만 비교하며, 영상이 끊기거나 크기가 바뀌면 비교 기준을 지운다. 돌아온 첫 프레임의 차이를 움직임으로 세지 않는다. 기존 35% 임계값·700ms 간격은 유지하고 처리 시간에 따라 100~300ms 간격을 조절한다. 호환 모드는 최소 167ms와 작은 촬영 요청으로 부하를 줄인다. 화면 변화 횟수는 학생의 정확한 운동 수행 횟수가 아니다.
- QR 세 흐름은 공통 카메라 세션으로 연결했다. 자동/호환 해독은 각각 8/5fps이며 QR 형식만 읽고 촬영 요청도 제한한다. 멈춘 영상에서는 해독을 일시 정지하고, 새 프레임을 확인한 뒤 재개한다. 유효 QR은 한 번만 받아 카메라 종료 후 기존 입장·코드 입력·미션 처리에 전달한다.
- 준비 중 취소·모드 전환·화면 제거는 해당 시도의 고유 DOM과 스트림만 정리한다. 브라우저 권한 대화상자는 웹앱이 강제로 닫을 수 없으므로, 응답 대기 중에는 종료 대기를 알리고 중복 카메라 요청을 막는다. 늦은 허용 응답이 오면 그 스트림을 정리하며 QR을 제출하지 않는다. 화면이 먼저 제거돼도 이전 시도의 라이브러리가 준비를 마치고 종료할 수 있도록 별도 비표시 표면을 잠시 유지한 뒤 제거한다.
- 실제 라이브러리 시험에서 start 완료와 영상 playing 사이의 준비 경쟁을 발견했다. 초기 UI가 준비되기 전에는 pause를 호출하지 않고 입력 게이트로 차단하도록 수정했다. 의도된 종료 중 라이브러리의 onabort 핸들러가 던지는 오류도 해당 소유 표면의 정리 단계에서 해제했다. 활성 중 오류는 공통 감시기로 처리한다.
- 학생 입장은 기존 동일 출처 `/join` 주소만 허용한다. 탐사 코드는 기존 토큰 형식을 유지하고 방 검증은 기존 RPC가 수행한다. 미션 QR은 현재 수업의 미션 ID와 기존 6종 보물 코드만 허용한다. 외부 URL·임의 보물은 열거나 제출하지 않는다. 기존 점수·쿨다운·수업 상태 검사와 DB 권한은 유지하며 DB 스키마나 환경 변수는 바꾸지 않았다.
- 새 회귀 검사 17개는 fresh-frame 차단, 단일 재생 복구, 모션 비교 기준 복원, 권한 지연·시간 초과, QR 중복·외부 입력 차단, 수락 전 정리 취소를 포함한다. 기존 손목·기울기 카메라 검사 23개와 함께 실행한다.
- Chrome에서 합성 캔버스 스트림과 **실제 html5-qrcode**로 입장·탐사·미션 QR 해독, 외부 주소 거절, 호환 모드, 영상 pause 복구, 권한 대기 중 취소 및 컴포넌트 제거 후 늦은 응답 정리를 확인했다. 모션 캠의 합성 움직임 카운트·정적인 영상의 카운트 중지·모드 전환도 확인했다. 수업방·점수 DB에는 시험 결과를 쓰지 않았다. QA 페이지는 배포에서 제외한다.

영상·픽셀 배열·미리 보기·처리 모드는 기기 메모리에서만 처리한다. QR 원문을 로그나 브라우저 저장소에 새로 남기지 않는다. 유효한 기존 입장 주소와 미션 ID만 기존 처리로 전달한다. 실물 S25의 카메라 촬영·발열·조명·실제 종이 QR 정확도와 실제 동시 수업은 별도 재시험이 필요하다.
