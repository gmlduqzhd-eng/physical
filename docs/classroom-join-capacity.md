# 수업 입장과 학교 와이파이

학생 입장은 기기별 익명 인증 후 PIN 또는 QR을 검증한다. 수업방에 15명 제한은 없다. 학생 번호는 수업별 1~99이고 중복 번호는 거절한다.

2026-10-22 운영 점검에서 두 가지를 재현했다.

- 정상 PIN 재입장을 반복해도 실패 횟수가 증가해 13번째부터 `rate_limited`가 반환됐다. `classroom_join_failed_attempts` 마이그레이션은 정상 코드에 대한 시도를 차감하고, 기존 참여자는 현재 유효한 자기 모둠 코드로 재입장할 수 있도록 한다. 유효하지 않은 코드의 시도는 사용자별 15분에 12회로 제한하며 동시 요청도 원자적으로 계산한다. 번호 중복·별명 오류는 코드 추측 실패로 세지 않는다.
- Supabase Auth의 익명 로그인 한도가 IP당 시간당 30회였다. 교사 인증 1회 뒤 새 기기 40개를 동시에 인증하자 29개 성공, 11개 HTTP 429가 발생했다. 학교 와이파이가 공인 IP를 공유할 수 있으므로 운영 대시보드의 Authentication → Rate Limits → Rate limit for anonymous users를 **120 requests/h/IP**로 변경했다. 다른 인증 한도는 변경하지 않았다. 이 설정은 Git/Vercel 배포와 별도로 Supabase에 저장된다.

120은 동시 접속 인원수가 아닌 **한 시간 동안 새 익명 인증을 만드는 횟수**다. 기존 세션은 재사용한다. 인증을 브라우저 전체 공용 계정으로 합치거나 학생별 권한 검증을 해제하지 않는다.

오류를 구분한다. `rate_limited`는 기기별 잘못된 코드 입력 제한이며 이전 수업 이어가기를 안내한다. Auth HTTP 429는 같은 인터넷에서 새 기기의 요청이 몰린 경우로 안내한다. 실제 접속 인원이 많다는 문구로 오해시키지 않는다.

## 회귀 검증

`CLASSROOM_LIVE_TEST=1`을 명시하고 `node node_modules/tsx/dist/cli.mjs scripts/classroom-join-concurrency.ts`를 실행한다. Windows에서는 OS 인증서 저장소를 사용하는 검증된 HTTPS 요청을 병렬 실행한다. 토큰은 메모리에만 보관한다.

스크립트가 출력한 이번 실행의 합성 교사 ID와 run UUID를 확인해 해당 테스트 계정에만 짧은 교사 권한을 부여한 다음, `work/prepared/concurrency-control.json`에 `{"teacherReady":true}`를 저장한다. 테스트 계정의 메타데이터 `physical_test_run`이 해당 run UUID와 일치해야 한다. 실제 교사 계정이나 다른 방을 수정하지 않는다. 수정 후 전원 인증 성공도 강제하려면 `JOIN_EXPECT_AUTH_PASS=1`을 설정한다.

40개의 독립 세션으로 PIN·QR 40건 동시 입장, 출석 번호 보존, 각각 20회 재입장, 번호 중복 오류 15회 후 재시도, 잘못된 코드 20건 동시 요청의 12회 제한, 모바일·PC 실제 화면 입장을 검증한다. 생성한 방과 템플릿은 finally에서 삭제한다. 테스트 종료 후 이번 run의 계정·권한만 관리 연결로 정리한다. 결과 JSON에는 토큰·PIN·QR 코드를 넣지 않는다.
