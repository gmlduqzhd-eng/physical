# 협동 게임 경험 개선 구현

기준 main: `62d6bec1481eb71e7af03689bada24f854713635`.
기존 게임 ID·기록·명단·점수·교사/학생/TV 권한·만료/복구·보관 정책을 유지한다.
라이트 크림 올리브 / 다크 펄 차콜 토큰을 사용한다. 실제 움직임과 입력·신고를 구분한다.

## 사용 흐름과 주요 변경

- 메인에서 대표 경험 3개를 먼저 보여 주고 기존 교사·학생·혼자 하기·전체 활동 입구를 유지한다.
- `/try/map`, `/try/ship`, `/try/loop`: 로그인 없는 짧은 원리 체험. 가상 모둠·가상 조종임을 표시하고 실제 입력에 따라 길·물리 조종·박자 결과가 바뀐다. 기존 대표 게임의 도움말에서도 같은 체험을 연다.
- `/together`: PC/TV 한 대로 신호·박자·역할 교대 놀이를 진행한다. 3초 준비 후 20초씩 3라운드를 안내하며 라운드 사이는 진행자가 넘긴다. 일시정지·다시 준비·선택 음성·앉은 동작·발표용 전체화면을 제공한다. 수업방·명단·점수는 생성하지 않는다.
- 새 비밀지도 원정: 첫 길·마지막 길·운반 약속을 분산한다. 방문 확인 후 모든 모둠이 맞는 길과 운반 약속에 합의해야 다음 관문을 연다. 혼자 연습에서는 합친 단서를 제공한다. 자동 경로는 여섯 가지이며 교사의 명시적 경로 선택은 보존한다.
- 6개 대표 원정에 구체적인 역할 행동·접근 가능한 대안·짧은 행동 안내·선택 음성을 연결한다. 완료/준비 모둠은 다른 모둠의 도움 신호에 응답할 수 있다. 교사 전광판에도 도움 신호를 표시한다.
- 지도는 열린 경로와 약속, 우주선은 도착 정거장과 경계 접촉, 리듬은 실제 입력 합주를 끝장면으로 보여 준다. 구조·그림자는 기존 발사 비교·따라가기 결과와 게임별 끝장면을 연결한다. 연습 재시도는 완료 상태를 초기화한다.
- `/lessons`: 공간·기기에 맞춘 수업 순서와 안전 안내를 제공한다. 받은 구성은 한 장에서 확인한 뒤 기존 교사 인증과 안전 확인을 거쳐 새 방을 만든다. 현장 효과가 검증된 사례로 표시하지 않는다.
- 구성 공유는 `v/game/groups/minutes/settings`만 엄격하게 허용한다. 방 ID·학생 정보·점수·입장 코드·복구키·토큰은 받지 않는다. Google 로그인 복귀에는 검증한 공개 조건만 10분 동안 보관한다.

주요 코드: `src/domain/{cooperativeMap,movementRoles,playRecipes,sharedScreen}.ts`,
`src/presentation/{PlayExperiencePage,SharedScreenLesson,LessonRecipes}.tsx`,
`src/presentation/flagship/`의 체험·도움·끝장면 컴포넌트.
기존 홈·수업 준비·원정 연결부를 수정했고, 배포 검사와 교사 준비실 파일 허용 목록에도 새 의존성을 반영했다. 의존 패키지는 추가하지 않았다.

## 신규 DB 변경과 보존 범위

신규 migration: `20261115094331_cooperative_map_and_group_support.sql`.

- 실제 CLI `migration new --help` 확인 후 신규 파일을 생성했다. 기존 적용 migration은 수정하지 않았다.
- 검토한 `physical_internal.expedition_action`의 본문만 보완한다. 기존 OID·소유자·ACL·서명·실행 속성·고정 search_path를 유지한다. 예상 본문 해시/보안 속성이 다르면 변경 전에 중단한다.
- CRLF/LF 차이만 정규화한다. 의미가 다른 코드를 허용하는 공백 정규화나 무검증 본문 교체는 하지 않는다.
- 기존 실행 중인 원정과 버전 없이 시작한 원정은 원래 지도 규칙을 유지한다. `mapVersion:2`로 새로 시작한 원정과 그 보스 하위 지도만 새 규칙을 사용한다.
- 테이블·열·RLS·GRANT·publication·cron·운영 비밀·보관/복구 정책은 바꾸지 않는다. 기존 행을 UPDATE/DELETE하는 데이터 변환도 없다.
- 실제 이동 여부를 RPC가 확인한 것으로 표시하지 않는다. 방문/합의/역할 교대/도움은 입력·신고 기록이며 교사 확인과 기존 점수 검토 절차를 유지한다.

향후 적용 순서(이번에는 실행하지 않음):

1. 기존 DB는 백업과 현재 정의를 확인하고, 이전 37개 migration 적용 상태를 확인한다. `supabase_schema.sql`이나 빈 DB 설치 파일을 운영 DB에 실행하지 않는다.
2. **신규 파일 하나만** 적용한다. 예상 정의가 다르면 중단 후 검토한다. 과거 migration을 재실행해 맞추지 않는다.
3. 데이터·정책·권한 보존과 교사/학생/TV 동작을 확인한 후 앱을 배포한다. 기존 실행은 계속 기존 규칙이며 새 원정부터 새 지도를 사용한다.

빈 격리 DB 설치는 기존 안전 경로인 `supabase/install_empty.psql`을 사용한다.
빈 DB 사전 검사 → 기본 스키마(클라이언트 접근 닫힘) → **38개 migration 오름차순** → 최종 접근 활성화 → 검증 순서다.

DB 대상은 Windows의 분리된 VM 안에서 실행한 **native Supabase 테스트 스택**이다.
운영 Supabase 프로젝트에 연결하거나 유료 테스트 프로젝트를 생성하지 않았다.
SQL 합성 데이터는 ROLLBACK했고 REST 검사용 자기 소유 방·Auth 사용자·bootstrap 행만 정리했다. 기존 무관 객체/합성 보존 행과 publication 등록은 유지했다.

검증 중 수정한 내용: 역할 순환의 중복 배정, 기존 역할 함수 import 누락,
로그인 fixture의 세션 기한, 페이지 새 방문마다 라이트로 돌아가는 정책에 맞춘 다크 검사,
과거 migration 재실행 방지 조건을 우회하지 않는 rollback 전용 구형 함수 fixture,
SQL 소스/본문의 CRLF 처리, 전체화면 전환 완료 대기.
원래 권한이나 안전 검사를 느슨하게 만들어 통과시키지 않았다.

## 미실행 항목과 한계

- 실제 교사 Google OAuth 로그인, 운영 수업방, 운영 JWT/Realtime, 운영 Advisor 재검사, 운영 DB 적용, GitHub push, Vercel 배포는 수행하지 않았다.
- 모바일·태블릿은 브라우저 화면 폭 검사이며 실물 터치·센서·카메라 시험이 아니다. 음성 합성의 한국어 발음과 실제 TV 출력도 기기별로 확인하지 않았다.
- 실제 학생의 재미·지속 참여·운동량·교사의 진행 부담은 수업에서 검증해야 한다. 버튼·자기 신고·시간 경과를 신체 활동의 증거로 취급하지 않는다.
- 빌드는 통과했고 기존 500kB 초과 chunk 크기 안내는 남아 있다. 이를 런타임 오류나 검증 통과로 대체하지 않는다.
