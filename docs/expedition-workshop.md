# 대표 원정 수업 확장 · 구현 및 검증

2026-11-09. 사용자의 검증 재개 요청에 따라 아래 10개 기능의 자동 시험, 실제 화면 조작, 운영 DB 적용 후 권한 검사를 수행했다. 운영 주소는 학생·수업방 https://physical-pi.vercel.app, 별도 교사 준비실 https://physical-teacher-studio.vercel.app 이다. 배포별 READY 상태와 커밋은 작업 결과 보고서에 기록한다. 물리 기기와 실제 수업 효과를 검증했다는 의미는 아니다.

## 화면과 사용 흐름

교사 시작 `/teacher`, 준비 `/teacher/setup`, 원정 모음 `/expeditions`, 본 기기 연습 `/solo/play/expedition-*`를 유지한다. 기존 활동 탐색·수업방·미션·점수 승인 흐름은 유지한다. 추가 기능 때문에 새 API 키나 환경 변수는 필요하지 않다. 기존 Supabase와 별도 교사 Gemini 설정을 그대로 사용한다.

## DB 및 권한

운영 DB 적용 완료: `20261109054736_expedition_workshop.sql`, `20261109060342_expedition_workshop_compatibility.sql`.

- 기존 private 원정 테이블의 `config`, `groups` JSON을 확장한다. 새 public 테이블이나 공개 SELECT 정책을 만들지 않는다.
- 기존 RPC 진입점, 교사 소유권·모둠 소속·방 만료·교사/TV 읽기 접근 검사를 유지한다. 내부 보조 함수는 public/anon/authenticated EXECUTE를 취소한다.
- 학생은 자기 모둠의 역할 교대·거친 준비 상태 보고만 변경할 수 있다. 모둠 인원·난이도·수업 단계·관찰 태그는 교사 소유자만 수정한다. TV는 읽기만 한다.
- 변경에는 원정 실행 ID와 요청 ID를 요구하고 중복 요청을 억제한다. 단계 변경은 진행 중, 인원·난이도 조절은 대기·일시정지 중에만 허용한다.
- 모둠별 코스 변경은 해당 게임 진행을 초기화한다. 기존 점수·승인된 제출을 삭제하지 않는다. 지도·보스의 관문이 열린 뒤에는 새 원정을 열어야 한다.
- 보스 경로에 포함된 모든 관문의 실행 ID를 묶고 이전 관문을 건너뛰는 직접 입력을 막는다. 보스 결과는 각 관문의 기여 기록을 합쳐 보여준다.
- 기존 방 FK와 방 삭제 절차를 그대로 따른다. 새 상태도 수업 종료 후 7일 보관 및 소유 교사·관리자의 즉시 삭제 대상이다. 시험용 방 2개와 전용 템플릿·CLI 시험 인증 사용자 2개만 정리했다. 실제 브라우저 인증과 기존 수업 자료는 보존했다.
- 박자 배치 버전으로 기존 방의 고정 패턴과 새 편집기 패턴을 구분한다. 기존 클라이언트가 설정 없이 새 원정을 열어도 기존 박자 규칙을 유지한다.

## 개인정보와 AI 경계

- 역할 자리 번호는 사람·계정과 연결하지 않는다. 교대 버튼 횟수는 실제 전원의 수행 증명이 아니다.
- 카메라 영상·얼굴·랜드마크·궤적·센서 각도·기기 식별자는 새 준비 상태 전송에 포함하지 않는다. 준비 상태는 종류, 상태 enum, 서버 수신 시각만 모둠에 연결한다. 생체 평가가 아니다.
- 공개 수업 연결에는 활동 ID·학년군·목표·장소·기기·분 단위 수업 시간만 포함된다. AI 초안·관찰 태그·인원·학생 정보·쿠키·접근 코드는 넘기지 않는다. HTTPS 요청 경로에 넣지 않고 fragment로 넘긴다.
- Google 로그인 중에는 검증된 공개 수업 조건이나 꾸러미 선택만 `sessionStorage`의 `physical_teacher_public_setup_v1`에 최대 10분 보존하고 복귀 때 소비·삭제한다. 세션 저장소를 사용할 수 없으면 보존하지 않는다.
- 명시적 편집기 저장은 `localStorage`의 `physical-workshop-v1`에 허용된 설정만 남긴다. 학생·모둠 ID, 결과, 관찰, 미디어는 없다. 편집기에서 직접 지울 수 있다.
- 관찰 태그는 교사에게만 반환한다. 수정한 결과 요약은 화면 메모리에만 있고 교사가 다운로드한 파일은 직접 관리한다.
- 실제 Gemini 추천 1회를 생성해 수정·검토·채택·공개 조건 전달·다운로드까지 확인했다. 나머지 9항목의 계산·규칙·체험을 AI라고 표시하지 않는다. 서비스의 학습 이용 조건이나 결제 설정은 변경하지 않았다.

## 검증 결과와 수정 사항

- `npm run verify:release`: 106개 자동 검사, ESLint, 서버 TypeScript, 앱·Studio 빌드 통과. 카메라·기울기 수명주기 14개는 재현 신호 시험이며 실제 하드웨어 시험이 아니다.
- `supabase/tests/expedition_workshop.sql`: 60개 SQL 단언을 운영 적용 전 롤백 트랜잭션과 적용 후에 통과했다. 소유자·자기 모둠·타 모둠·TV·만료·중복 요청·오래된 실행 ID·비공개 함수 권한·세 보스 경로·관문 순서·기존 박자 호환을 포함한다. 경로별 독립 검사에서는 앞 단계 상태를 시험용으로 전진시켰다.
- 기존 `flagship_expeditions.sql`도 새 마이그레이션과 함께 롤백 시험을 통과했다. 실제 서버 물리 계산으로 우주선 정박 조건도 확인했다.
- 실제 화면에서 2개 모둠 방 생성, 학생 합류, 튜토리얼, 역할 교대, 지도 공동 관문, 보조 조작 구조 게임, 보스 완료, 교사 100점 승인·유지, 일시정지·재개, 수업 4단계, 종료 확인을 시험했다. 두 번째 모둠 일부 신호와 리듬 만점은 통제된 HTTPS 시험 입력을 사용했다. 화면의 실제 박자 클릭은 6%가 기록되어 완료 처리되지 않았고, 이후 합성 박자 신호로 성공 경계를 확인했다. 실제 학생 수행이나 사람의 리듬 정확도를 증명하지 않는다.
- 편집기 저장·불러오기·삭제, 저장된 20분 설정 복원, 준비 신호 12초 만료, 교사 관찰, 결과 초안 수정·검토·다운로드 내용 및 수정 후 채택 취소를 확인했다. 인쇄 버튼은 연결했지만 OS 인쇄·프린터 출력은 시험하지 않았다.
- 실제 Gemini `gemini-3.1-flash-lite` 추천에서 6인 입력에 4인 역할 문구가 포함됐다. 교사 확인 문구도 수정할 수 있도록 고쳤고 채택 전에 모둠 역할 확인 질문으로 수정했다. AI의 사실 정확성을 보장하지 않으며 출처 인용·교사 검토를 유지한다. 원본과 수정 채택본을 결과 폴더에 구분해 보관했다.
- 채택한 AI 추천의 활동과 허용된 공개 조건만 새 수업 준비 탭으로 전달하고 fragment를 제거하는 흐름을 확인했다. 개인정보·인증 정보가 전달되지 않았다. Google 복귀 조건의 10분 만료·1회 소비·잘못된 주소 거절은 자동 검사로 확인했다.
- 390·768·1440 CSS px에서 교사 편집기·결과, AI 추천, 전달된 수업 준비, 6개 원정 연습 화면 총 27조합의 문서 가로 넘침이 없었다. 브라우저 폭 재현이며 실제 스마트폰·태블릿 시험은 아니다.

주요 수정: SQL CASE 비교 구문, 모둠별 동일 박자 반복, 기존 방 박자 호환, 편집기의 저장 설정 초기화, 정지 상태의 리듬 강조, 10분 꾸러미 활동 불일치, 결과 항목 한국어 표시, 교사 확인 문구 편집과 재채택 처리. 로그인 후 나타난 시스템 오류는 두 Vite 서버가 공유한 모듈 캐시의 qrcode 504에서 재현됐다. 앱과 Studio의 캐시 폴더를 분리하고 의존성 사전 묶음을 지정한 뒤 해당 화면의 정상 실행을 확인했다.

운영 DB 보안 진단은 적용 전후 동일했다. 새 경고는 없었지만 기존의 무관한 번역·레거시 함수 EXECUTE 및 유출 비밀번호 보호 경고는 남아 있다. 비공개 원정 테이블의 의도된 무정책 RLS 알림도 존재한다. 프로젝트 전체에 보안 문제가 없다고 표현하면 안 된다. 관련 기준: [Supabase database linter](https://supabase.com/docs/guides/database/database-linter), [Auth password security](https://supabase.com/docs/guides/auth/password-security).

실행: 앱 `npm run dev`, 별도 Studio `npm run dev:studio` 및 `npm run dev:studio:api`. 배포는 main Git 연결과 Studio의 `npm run prepare:studio:deploy` 허용 목록을 각각 사용한다. 기존 서버 전용 비밀값은 환경 파일과 배포 설정에만 유지한다.

## S25 카메라 후속 보고

사용자는 이전 ‘잘 인식’ 답변 이후 **‘간헐적으로 인식됨’**이라고 보완했다. 지속적인 안정 인식이나 원인 해결로 판단하지 않는다. 반복 끊김 때 위치 조정·터치 대안 안내를 추가했다. 기존 confidence 경계를 낮추거나 인식되지 않은 값을 성공으로 유지하지 않는다. 갤럭시 S25의 실제 카메라·기울기 재시험과 실제 학교 수업 효과는 남은 검증이다.
