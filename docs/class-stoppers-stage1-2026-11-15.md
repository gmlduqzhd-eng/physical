# 수업 중단 원인 제거 1단계 (2026-11-15)

실제 40분 수업에서 진행이 멈추던 원인 다섯 가지를 고쳤다. DB 마이그레이션·환경 변수·권한 변경은 없다.

|번호|대상|반영한 동작|
|---|---|---|
|1|교사 로그인 유지|수업 앱 교사 쿠키 수명을 2시간에서 10시간으로 늘렸다. 교사 화면이 열려 있는 동안 20분마다 DB 교사 권한(2시간)을 다시 받고, Google 계정 세션은 이때 쿠키도 연장한다. 기존 공유 코드 세션은 연장하지 않는다. 별도 AI 준비실 쿠키는 2시간 그대로다.|
|2|로그인 만료 안내·복귀|만료되면 수업 화면 자리에 로그인 화면과 만료 안내를 보여 준다. Google 로그인 뒤에는 정해진 교사 화면(`/teacher/setup`·`/teacher/manage`·`/teacher/members`·`/teacher/room/<uuid>`)으로만 돌아간다. 임의 주소는 저장하지 않는다.|
|3|학생 활동 정지 완화|수업 상태 조회 간격을 1.5초에서 5초로 늘렸다(교사 정지·종료는 Realtime으로 즉시 전달). 마지막 확인 상태가 진행 중이면 연결 확인이 6회(약 30초) 연속 실패할 때까지 활동을 멈추지 않는다. 교사 정지·대기·종료와 방 접근 불가는 기존처럼 즉시 막는다.|
|4|점수 바로 반영|새 안내형 수업방은 만들 때 교사 점수 확인을 끈다. 수업 준비 마지막 단계의 체크로 교사 확인을 선택할 수 있고, 수업 화면의 `게임 점수 확인`에서 언제든 바꿀 수 있다. DB 기본값은 그대로다.|
|5|구형 제어판 링크·지난 설정|수업 진행 중에는 `/admin` 링크를 숨기고 종료 뒤 리포트용으로만 보여 준다. `지난 설정으로 빠르게 준비`는 가장 최근 설정을 채워 마지막 확인 단계로 이동한다.|

## 검증과 한계

- `npm run verify:release` 통과. 수업 상태 훅 회귀 시험을 새 기준(유예·장시간 단절·오프라인)으로 고쳤고, 로그인 복귀 경로 허용 목록 시험을 추가했다.
- 운영 Supabase, 실제 Google 로그인, 학교 Wi-Fi, 실물 기기에서는 시험하지 않았다. 배포 뒤 교사 계정으로 2시간 이상 열어 둔 수업방 제어와 새 수업방의 점수 즉시 반영을 확인해야 한다.
- 서버는 여전히 수업 상태·소속·만료를 검사한다. 유예 중 제출이 거절되면 기존 전송 대기열 규칙을 따른다.
