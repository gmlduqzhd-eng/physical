# Gemini 교사 도구 구현과 사용 안내

2026-10-20 기준. 학생 앱과 분리한 만 18세 이상 교사용 도구에 기존 1~10번 메뉴와 11번 참여 안내 메뉴를 구현했다. 1~5번과 7~10번은 실제 Gemini 호출 결과를 검증했고, 6번은 외부 전송 없는 규칙 분석이다. 11번은 모의 Gemini 응답·빌드·학생 화면으로 검증했으며 운영 API 실제 생성은 아직 확인하지 않았다. 7번 메모 원문 전체 요약은 제공하지 않는다.

## 실행

저장소 work/physical에서 각각 실행한다.

```sh
npm run dev:studio:api
npm run dev:studio
```

화면은 http://127.0.0.1:5174/ 이고 API는 루프백 8788이다. 기존 교사 접근 코드로 성인 교사 확인 후 로그인한다. 학생에게 이 화면이나 접근 코드를 공유하지 않는다. `npm run build:studio`는 별도 `dist-teacher`를 생성한다. 이 도구는 학생 Vercel 배포에서 제외되어 있다. 학생 DB·프로필·개인 이력을 읽지 않는다.

11번 학생 링크는 문구와 활동 ID만 URL 조각에 담고 학생 기록·인증 정보는 포함하지 않는다. 링크를 받은 사람이 문구를 바꿀 수 있으므로 학생 앱은 작성자의 신원을 보증하지 않는다. 교사는 공유 전 문구·안전·접근성을 확인한다. 학생 화면은 활동 준비·게임 중 접이식 안내·짝 활동 확인 화면에 문구를 표시한다. 화면 조작, 링크 열기, 타이머 종료는 실제 신체 움직임의 증거가 아니다.

AI 결과를 수정하거나 입력 조건을 바꾸면 검토·채택 상태를 해제한다. 채택본을 수업방에 자동 게시하거나 점수에 반영하지 않는다. 내보낸 텍스트의 수정 내용 포함 여부도 실제 다운로드 파일로 확인했다.

## 원문 검증

카탈로그는 기존 GAMES와 LESSON_GAME_CATALOG이다. 조건 필터는 사전 처리이며 AI라고 표시하지 않는다. Gemini가 활동과 원문 참조 번호를 선택하면 서버가 허용된 번호인지 확인하고 원문을 붙인다. 없는 번호·다른 활동의 인용·안전 자료가 아닌 안전 참조·누락된 단계·맞지 않는 지도안 시간·일부 새로운 안전 수치는 거절한다. 7·8번 첫 요약은 입력과 정확히 일치해야 한다. AI가 관찰하지 않은 장면을 추가하면 결과를 표시하지 않는다.

전체 생성 문장의 의미와 교육적 타당성까지 증명하는 검증은 아니다. 교사가 원문·현장·학생 참여 의사를 확인한다. 기존 카탈로그의 교육과정 및 안전 문구 자체를 공인 기준으로 재인증한 것은 아니다. 일부 응급·의학 활동은 AI 대상에서 제외했다.

## 환경 변수와 보관

로컬을 사용하는 경우 서버 전용 Git 제외 파일 `.env.gemini.local`에 GEMINI_API_KEY, GEMINI_MODEL, GEMINI_PUBLIC_DATA_REVIEWED를 저장한다. 기본 모델은 gemini-3.5-flash-lite다. 기존 gemini-3.1-flash-lite의 반복된 503 과부하에 대응해 다른 무료 티어 지원 모델로 변경했다. 2026-10-23 확인한 Google 공식 가격표에서 이 모델의 표준 텍스트 입력·출력은 무료 티어를 지원하며, 구조화 출력도 지원한다. 실제 요금 적용은 키가 연결된 Google 프로젝트 등급을 따른다. 앱은 결제를 연결하거나 요금제를 자동 변경하지 않는다. 키 저장 화면은 현재 기본 모델을 저장한다. 키를 채팅·댓글에 쓰거나 VITE_로 시작하는 변수에 넣지 않는다.

모델·무료 티어 확인: https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite / https://ai.google.dev/gemini-api/docs/pricing#gemini-3.5-flash-lite

교사 인증은 `.env.teacher.local`의 TEACHER_ACCESS_HASH와 TEACHER_SESSION_SECRET을 사용한다. 코드를 처음 만들 때만 `npm run teacher:setup`을 실행한다. 저장된 키는 사용자 교체·삭제 전까지 서버 파일에 존재한다. 로그아웃은 키 파일 삭제가 아니다.

Google에 보내는 것은 공개 활동 원문, 정해진 수업 옵션과 일반 조건이다. 7번은 일반 태그만, 8번은 범주 집계만 전송한다. 8번의 정확한 classSize·groupSize는 서버 최소 크기 검사용이며 Google 요청에서 제거한다. 실명·별명·번호·얼굴·연락처·개인 기록·학교 및 학급 ID·메모 원문은 스키마에서 받지 않는다. 6번은 숫자 기록도 외부 전송하지 않는다. 범주 집계도 맥락으로 재식별될 수 있으므로 최소 크기가 익명성을 보장하지 않는다.

정상 사용에서는 입력·출력을 서버 로그·DB·브라우저 저장소에 저장하지 않는다. 화면 메모리에는 새로고침·로그아웃 전까지 남고, 교사가 내려받은 파일은 직접 삭제해야 한다. 이번 검증에 사용한 공개·가상 시나리오 결과만 outputs에 별도 저장했다. 검색·외부 도구·파일 업로드·대화 이력·명시적 캐시는 사용하지 않는다. 제공자의 자동 캐시와 보관은 제공자 조건을 따른다.

무료 Gemini 입력·출력은 제품 개선과 사람 검토에 사용될 수 있다. 무료 서비스 전체에 대해 고정 보관 일수를 보장하는 근거는 확인하지 못했으므로 무보관으로 안내하지 않는다. 학교에서 승인한 공개·비기밀 조건만 사용한다. 무료 여부는 키의 Google 프로젝트 결제 상태에 따라 정해지고 앱이 자동 확인하지 못한다. 자동 유료 전환은 없다. 교사 요청은 분당 3회·동시 1개로 제한한다. 각 요청은 90초 안에서 일시적 서버 오류(500·502·503·504)에 최대 2회 자동 재시도하며, 대기는 2초·4초에 최대 1초의 무작위 지연을 더한다. 제공자의 Retry-After가 더 길면 이를 지키고 제한 시간을 넘으면 재시도하지 않는다. 결과 형식 보정은 1회까지이며 모든 원격 호출의 합은 최대 3회다. 429 한도·결제·인증·잘못된 설정·클라이언트 시간 초과는 재시도하지 않는다. 최종 실패 시 오류를 표시한다.

## 검증과 남은 범위

3~4학년군·협동·체육관·모둠별 태블릿·40분·24명/6명 모둠의 가상 수업 조건으로 9개 외부 작업의 실제 모델 결과를 저장했다. 지도안 합계 40분, 협동 미션 6명·10분, 비로 실내 전환 추천 3개, 성찰 질문을 확인했다. 6번 입력·수정·채택·지우기도 UI에서 확인했다. 실제 학생 자료를 쓰지 않았다. 단위 테스트 응답은 별도 명시된 테스트 자료이며 실제 AI 결과로 홍보하지 않는다.

`test:studio` 4개(9개 작업 SDK 전송 검증 포함), `test:teacher` 14개, 서버 타입 검사·빌드·린트를 통과했다. 기기 화면 크기 재검증 상태는 최종 전달 보고서에 기록한다. 실물 기기·실제 학생 수업 효과·전체 게임과 센서 동작은 이번 검증 범위에 포함되지 않는다.

교사별 개별 계정, 원문 메모 전체 AI 요약, 개인별 기록 외부 AI 분석은 제공하지 않는다. 학생 앱의 선택적 OpenAI 경로는 별개이며 크레딧 부족 상태에서 실제 성공을 주장하지 않는다.

### 화면 폭 추가 검증 (2026-10-20)
로그인한 인앱 브라우저에서 화면 크기 변경이 실제 적용됨을 DOM 측정으로 확인했다. 요청 폭 390·768·1440px에 대해 스크롤바 제외 본문 폭은 375·753·1425px였다. 기능 4~10의 입력 화면 21개 조합 모두 문서 가로 넘침이 없었다. 스마트폰 폭에서 기능 6의 숫자 입력과 로컬 결과 표시도 확인했다. 실물 기기·터치·센서·실제 수업 효과 시험은 포함하지 않는다. 실측 기록은 전달 파일 화면폭-검증.json을 따른다.

추가로 스마트폰 폭에서 실제 Gemini 성찰 질문 생성 → 문구 추가 → 교사 확인 → 채택을 수행했다. 내려받기는 채택 전 비활성, 채택 후 활성으로 확인했다. 동일한 실제 결과 화면도 본문 폭 375·753·1425px 모두 가로 넘침이 없었다. 해당 결과 화면의 스크린샷 3개와 모바일 채택 화면을 전달 폴더에 저장했다. 브라우저 크기는 검증 후 원래대로 복원했다. 이번 확인은 로그인 상태가 확보된 인앱 브라우저에서 수행했으며 Chrome 로그인 완료를 검증한 것은 아니다.

## 별도 온라인 배포 (2026-10-20)

교사 도구는 별도 Vercel 프로젝트 `physical-teacher-studio`에 배포한다. 프로젝트 ID는 `prj_qjH9VLy1bhmDD2vX6LX6nYono9xB`, 팀은 기존 `team_YZHSWFgCb4NEhjCA9nORvfin`이다. 학생 앱 `physical`의 API 및 배포 설정과 분리한다.

사용 주소: https://physical-teacher-studio.vercel.app
기존 교사 접근 코드와 성인 교사 확인으로 입장한다. 온라인은 독립 세션 서명키와 Secure·HttpOnly·SameSite=Strict 쿠키를 사용하며 유효 시간은 2시간이다. 로컬에서 로그인했어도 온라인에서는 다시 로그인해야 한다.

온라인 서버 환경변수는 `TEACHER_ACCESS_HASH`, 독립 `TEACHER_SESSION_SECRET`, `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_PUBLIC_DATA_REVIEWED=true`, `STUDIO_ORIGIN`이다. 키·해시·서명키를 Production Secret으로 저장했다. 키 값은 HTML·JS·상태 API로 내보내지 않는다. API 키 저장·교체 화면과 configure 경로는 온라인에서 제공하지 않는다. Vercel 설정에서만 관리하며 변경 시 재배포해야 한다. Vercel에 저장한 키는 설정에서 교체·삭제할 때까지 남으며 이전 배포본도 별도 관리해야 한다.

`npm run prepare:studio:deploy`는 `.studio-deploy`에 허용 목록의 파일만 복사한다. 이 묶음에는 학생 API, Supabase SDK 연결 코드, DB 자격 증명과 `.env` 파일이 없다. 출력 폴더는 Git에서 제외한다. 생성되는 `api/studio.ts`는 `server/studioHandler.ts`를 사용한다. 서버 처리 제한 120초, 모델 요청 제한 90초다. 루트 학생 프로젝트에는 해당 API가 추가되지 않는다.

이후 배포 절차: 준비 명령 → `.studio-deploy`를 위 교사 프로젝트에 연결 → Production 환경변수 확인 → `vercel deploy --prod --skip-domain` → 인증·출처·개인정보 거절 및 생성 검사 → 검증한 배포를 `vercel promote`로 운영 승격한다. 현재 교사 프로젝트는 Git 자동 배포에 연결하지 않았으므로 일반 저장소 push만으로 교사 서비스가 갱신되지는 않는다. 학생 프로젝트의 기존 Git 자동 배포는 유지한다.

기본 보호로 강한 교사 코드, 출처 검사, 요청 8KB 제한, 인증별·인스턴스별 생성 분당 3회와 인스턴스 동시 1개를 적용한다. 로그인은 인스턴스별 IP당 15분 8회다. 서버리스 인스턴스가 여러 개일 때 전역 제한을 보장하지 않는다. 공동 운영·공개 모집 전에는 교사 개별 계정과 공유 저장소 기반 속도 제한을 추가해야 한다. 학생에게 교사 주소·코드를 배포하지 않는다. 결과와 입력을 앱 DB에 저장하지 않지만 Vercel은 요청 메타데이터·운영 로그를 제공자 정책과 프로젝트 설정에 따라 처리한다. 앱의 프롬프트·응답·자격 증명 로깅은 추가하지 않았다. Vercel 로그 전체의 고정 무보관 기간을 보장하지 않는다.

온라인 경로 테스트 `npm run test:studio:deployment`는 실제 HTTP로 인증·학생 쿠키 거절·성인 확인·출처·크기 제한·개인 필드 거절·키 설정 경로 부재·쿠키 속성을 확인한다. 실제 서버 검증은 `scripts/studio-live-deployment.ts`를 사용하며 공개 가상 수업만 입력한다. 내려받은 검토본과 기존 로컬 파일의 관리 책임은 이전 안내와 같다.

### 운영 공통 제한

온라인 별도 교사 서버는 서버 전용 `STUDIO_LIMIT_URL`, `STUDIO_LIMIT_KEY`, `STUDIO_LIMIT_SECRET`를 사용해 전용 `physical_studio_limits` 카운터 RPC만 호출한다. 학생 수업방·프로필 데이터를 읽지 않는다. Secret은 최소 32자이고 DB에는 SHA256 해시만 별도 프로비저닝한다. `.env.studio-limit.local`과 프로비저닝 파일은 Git 및 배포 대상에서 제외한다.

전체 인스턴스 공통으로 동시 생성 1개(중단 시 130초 리스 만료), 1분 창당 3개, 한국 날짜 기준 하루 100개의 생성 요청을 허용한다. 실패한 생성 요청도 포함한다. 내부 재시도/형식 보정은 요청당 최대 3회이므로 100회는 원격 모델 호출 100회나 금액 한도를 뜻하지 않는다. 한도 도달 시 429와 Retry-After, 제한 서버 장애/설정 누락 시 503을 반환하며 모델을 호출하지 않는다. 로그인은 IP당 15분간 8회로 모든 인스턴스에서 공유한다. 로컬 루프백 시험 서버의 한도는 별도다.

제한용으로 전송·저장하는 정보는 원본 IP가 아닌 HMAC 로그인 식별값, 카운터·만료시각, 무작위 리스 토큰, 일일 총횟수뿐이다. 학생 정보·교사 코드·수업 조건·초안을 넣지 않는다. 만료 카운터와 리스는 다음 요청 시 청소되므로 무조건 정해진 시각에 삭제된다고 보장하지 않는다. 일일 집계에는 개인 식별값이 없다. 새 프로젝트에서는 마이그레이션 후 별도 비밀 해시 프로비저닝 없이는 차단된다.
