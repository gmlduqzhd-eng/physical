# 여섯 가지 대표 협동 원정

2026-11-09 구현. 기존 자료실·수업방·모둠 미션·점수 검토 흐름을 유지하고 `/expeditions`에 새 입구를 추가했다. 이 문서는 실제 구현과 검증 범위를 기록하며 교육 효과나 신체 측정 정확도를 보장하지 않는다.

## 사용 순서

1. 메인 또는 교사 시작 화면의 **몸으로 연결하는 여섯 가지 원정**을 연다.
2. 원하는 게임의 **이 원정으로 수업 준비** → 모둠·시간 → 안전 확인 → 수업방 생성.
3. 수업방의 **대표 원정 진행 → 원정 열기 → 새 원정 시작 확정**을 누른다. 학생 모둠 QR과 지도용 탐사 지점 QR은 서로 다르다.
4. 지도/보스전은 **탐사 지점 안내판 열기**에서 세 안내판을 인쇄해 교사가 정한 걷기 동선에 배치한다. 다시 원정을 열면 이전 지점 코드가 만료된다.
5. 학생은 기존 수업방 모둠 QR로 입장한다. 교사가 수업을 시작하면 활동을 진행한다. 일시정지/종료/권한 만료 시 서버가 쓰기를 거절한다.
6. 완료 후 모둠이 역할 교대와 수행을 확인하고 결과를 제출한다. 기존 교사의 점수 승인·검토 절차를 사용한다.

기기 없이 수업을 먼저 살펴보려면 **본 기기에서 연습**을 사용한다. 연습은 다른 기기와 연결되지 않으며 수업방 진행을 대신하지 않는다.

| 게임 | 실제 앱 기능 | 준비·판정의 한계 |
|---|---|---|
| 움직이는 비밀지도 | 모둠별 다른 단서, 원정마다 바뀌는 경로/지점 코드, 전 모둠 정답 투표로 관문 개방 | 모둠당 1대·지점 3개. QR 방문과 실제 걷기는 같지 않으므로 짝/교사가 이동 확인 |
| 모둠 중력 우주선 | 같은 모둠의 서로 다른 인증 기기가 두 축을 분담, 서버 물리 계산·감속·세 정거장 도킹 | 실제 공동 조종은 2대. 기울기 신호가 없으면 중립. 보조 슬라이더는 자동 동작 측정이 아님 |
| 바디루프 발전소 | 4박 준비·8박 입력·서버 박자 오차 계산, 모둠 루프의 WebAudio 합주 | 소리는 합성음이며 마이크 녹음 없음. 몸으로 표현했는지는 사람 확인 |
| 몸으로 조준하는 바람 구조대 | 로컬 자세 모델의 오른팔 각도 추정·충전 타이밍·바람 탄도·3개 구조 목표 | 거치 카메라 권장. 터치 연습은 별도 표기. 탄도는 가상 게임이며 실제 투척/자세 평가 아님 |
| 시간차 그림자 연구소 | 로컬 손목 좌표 8개를 잠시 기억, 같은 길/좌우 반전/역순 따라가기 | 기기 메모리에서만 처리. 지우기·종료 시 삭제. 자세/운동 능력 검사 아님 |
| 우리 반 보스 원정 | 위 지도→우주선→리듬 세 관문을 묶고 전체 모둠 완료를 서버 확인, 교사 환경 이벤트 3회 | 보스전 자체는 생성형 AI가 아닌 서버 상태/규칙. 하위 관문 건너뛰기 차단 |

## 개인정보·접근 권한

- 새 외부 AI API 호출이나 새 비밀키는 없다. 기존 교사 AI 준비실은 별도 인증·별도 서버를 유지한다.
- 카메라는 버튼을 눌러 동의/권한을 받은 뒤에만 시작하며 오디오 권한을 요청하지 않는다. 영상·얼굴·전체 랜드마크·손목 경로를 서버에 전송하거나 저장하지 않는다. 프레임은 같은 기기의 MediaPipe CPU 추론에 사용하고 현재 오른팔/손목 값만 게임에 전달한다. 숨김·이동·중지·일시정지 시 카메라를 종료한다.
- 자세 모델/런타임은 같은 사이트에서 내려받는다. 배포 빌드에서만 Google 공식 버전 URL의 모델을 내려받아 고정 SHA256을 검사한다. 사용자의 영상이 Google 모델 API로 전송되는 구조가 아니다.
- 서버 저장은 방/모둠 ID·게임 진행·축 입력·박자 시점·참여 방식·중복 방지용 요청 ID 등이다. 축 소유권 확인을 위한 임시 Auth ID는 private 테이블에서만 사용하고 다른 모둠/TV 응답에 노출하지 않는다. 개인 운동 이력을 만들지 않는다.
- `physical_internal.expeditions`는 RLS 및 직접 접근 차단, 검증된 RPC만 사용한다. 교사는 자기 방, 학생은 자기 모둠, TV는 허용된 방의 읽기만 가능하다. 학생에게 다른 모둠 단서/지점 코드/컨트롤러 인증 ID를 주지 않는다.
- 수업방 삭제 시 FK CASCADE로 원정 상태도 삭제한다. 기존 정책인 **수업 종료 후 7일 보관·교사/관리자 즉시 삭제**를 따른다. 별도의 개인별 영구 기록을 추가하지 않았다. 기기 연습 결과는 기존 로컬 활동 기록 흐름을 사용한다.
- 입력 시간/코드/클라이언트 완료 보고는 실제 운동 수행의 증명이 아니다. 결과 화면에 자동 추정·터치 연습·짝 확인을 구분하고 교사의 최종 검토를 유지한다. 공식 성취기준은 임의 부여하지 않고 **연계 확인 필요**로 표시했다.

## 실행·배포

기존 서버 환경 변수를 사용한다. 새 키는 필요 없다.

```sh
npm ci
npm run prepare:vision
npm run dev -- --host 127.0.0.1 --port 5173
npm run verify:release
```

처음 준비 시 약 35MB의 ML 자산을 생성한다. `public/vision`은 Git에서 제외하고 `npm run build`가 고정 버전 SDK 자산과 모델을 준비한다. Vercel 업로드에는 준비 스크립트와 Apache 라이선스가 포함된다. 카메라는 HTTPS 또는 localhost에서 실행한다. 교사 스튜디오 배포에는 게임 카메라 UI/ML 자산을 넣지 않고 활동 메타데이터만 포함한다.

신규 DB 마이그레이션 세 개(원정 상태/RPC, 런타임 입력 검증, 보스 단계 검증)를 순서대로 적용해야 한다. 실제 연결 프로젝트에는 적용했다. 다른 프로젝트의 인증·교사 프로비저닝은 기존 수업방 보안 문서를 따른다.

## 검증 결과와 남은 현장 시험

- 배포 전 release 검사: ESLint, 서버 NodeNext, 기존 런타임 22, 교사 16, 스튜디오 12, 배포 1, 대표 원정 6, 운영 8, 회귀 12, 방 갱신 5 검사 및 학생/스튜디오 빌드 통과. 마지막 UI 보완 후 관련 타입·린트·원정 검사와 빌드를 다시 확인한다.
- 실제 연결 DB의 BEGIN/ROLLBACK 시험: 자기 모둠 단서, 타 방/모둠 접근 차단, 학생 초기화 차단, 지점 코드, 3모둠 3관문, 서로 다른 조종자 및 서버 3정거장 도착, 박자 점수, 일시정지/종료/만료, 보스 순서·이벤트 한도 통과. 가상 시계로 물리 진행을 가속한 합성 시험이며 실제 기기 지연 시험이 아니다. 시험 자료는 롤백했다.
- 실제 브라우저: 지도·구조대·그림자 결과 제출, 보스 세 관문과 결과, 우주선 보조 키보드 조작, 리듬 4/4·100% 입력 및 합주 연결 확인. 터치 대안 시험이며 실제 학생 운동 수행을 관찰한 것이 아니다.
- 여섯 게임 × 390/768/1440 폭: 실제 client 폭 375/753/1425에서 18건 가로 넘침 없음. 실물 스마트폰/태블릿과 터치 제스처·센서·카메라 정확도/수업 효과는 미검증이다.
- 같은 출처의 실제 모델을 빈 캔버스로 실행: 정상·포즈 0개, 관찰된 자산 출처는 localhost뿐. 카메라 영상이나 실제 학생은 사용하지 않았다. 실제 조명·옷·가림·저사양 기기의 인식률/속도는 현장에서 소규모 시험해야 한다.
